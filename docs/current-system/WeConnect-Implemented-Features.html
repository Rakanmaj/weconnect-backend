02 · Working capabilities

Six implemented areas with database persistence

WEEK 101

Accounts & secure sign-in

  • Developer and company registration
  • Admin accounts created through a private server command
  • Login, logout and role-protected portals
  • Unique email addresses; duplicate signup prevented
  • Scrypt password hashing; no plaintext password storage
  • HttpOnly session cookies; 7-day database sessions
  • Refresh/restart persistence; logout revokes access

/login · /register · /admin/login

WEEK 202

Developer profile & onboarding

  • Nine saved steps with Continue, Back and Save draft
  • Personal details, phone, bio and education
  • Preferred position, experience and career goals
  • Selected skills; GitHub, LinkedIn and portfolio links
  • CV, certificates, weekly hours and project preferences
  • Edit, save and reload real PostgreSQL profile data
  • Approved accounts can save an assessment career path

/developer/onboarding · /developer/profile · /developer/career-path

WEEK 203

Company profile & team workspace

  • Company details, website, industry, size and contact
  • Business registration number, country and documents
  • Email invitations expire in 7 days and work once
  • Accept with the matching verified company account
  • Owner / Admin: invite, change roles and revoke members
  • Evaluator / Recruiter: view the workspace team roster
  • Switch between your own and joined team workspaces

/company/profile · /company/team

WEEK 204

Real private file uploads

  • CV: PDF up to 5 MB
  • Certificates, ID and business documents: PDF / PNG / JPEG, 10 MB
  • Profile photos: PNG / JPEG up to 2 MB
  • 10 files and 50 MB total per account
  • File signature, MIME, size, origin and ownership checks
  • Actual file bytes stored in PostgreSQL BYTEA
  • Owners and platform admins can download; owners can remove

POST /api/files/:kind · GET / DELETE /api/files/:id

WEEK 205

Account submission & admin review

  • Submit a verified email, completed profile and required files
  • Real developer and company review queues
  • Approve, reject or request more information
  • Reviewer feedback and full history visible to the owner
  • Update information and resubmit for another review
  • Revision checks prevent conflicting / stale decisions
  • Changing reviewed details or evidence returns status to Draft

/developer/verification · /company/verification · /admin/*-verification

WEEK 206

Email verification & account recovery

  • Email verification: single-use link valid for 24 hours
  • Password reset: single-use link valid for 30 minutes
  • New requests replace previous links of the same type
  • Action tokens stored as SHA-256 hashes
  • Successful password reset revokes all login sessions
  • Known and unknown reset emails receive the same response
  • Current delivery: private .local/mail files; SMTP supported

/register/verify-email · /login/forgot-password · /login/reset-password

Corrections and new evidence can be resubmitted. Changing reviewed profile information or documents returns the account to Draft. Conflicting admin decisions are rejected through revision checks.

What the three verification stages mean

Email verified: the email link was consumed successfully.
Account verified: a platform admin approved the profile and documents.
WeConnect performance badge: a separate later feature based on demonstrated work. Account approval does not award this badge.
